# Подработка 24 — развёртывание

## 1. Локальный запуск (с API и SQLite)

```bash
cd server
pip install -r requirements.txt
```

Создайте `server/.env` (см. `.env.example`) и впишите токен из @BotFather:

```
BOT_TOKEN=123456789:AAF...
ADMIN_TG_IDS=123456789      # ваши telegram id (числовые) — права администратора
BASE_URL=https://myservice.onrender.com   # публичный адрес (для ссылок в уведомлениях)
BLOCK_THRESHOLD=3           # жалоб до автоблокировки аккаунта (по умолчанию 3)
GROUP_ID=@podrabotka_orders # канал-витрина, куда бот публикует объявления
BANNED_WORDS=               # свои стоп-слова через запятую (в дополнение к встроенным)
```

Запуск (из корня проекта):

```bash
python server/run.py
```

Откройте `http://localhost:8137`. FastAPI отдаёт и API (`/api/...`), и статику (index.html, css, js, fonts) — это единый сервер.

- Без `BOT_TOKEN` сервер работает в **демо-режиме**: вход под демо-пользователем «Иван Петров», подпись initData не проверяется.
- С `BOT_TOKEN` проверяется подпись `initData` (HMAC-SHA256). Вне Telegram или при неверной подписи — 401, приложение переключается в офлайн-режим (localStorage).

## 2. Публикация в Telegram

### Про Vercel

**Vercel для этого проекта не подходит.** Vercel рассчитан на статику и serverless-функции (Node), а наш бэкенд — **постоянный Python-процесс с SQLite**. В serverless-окружении файл БД эфемерный: данные будут теряться между вызовами. Для FastAPI + SQLite выбирайте **Render**, **Railway** или VPS (ниже). Если позже захотите Vercel — надо будет заменить SQLite на Supabase/PostgreSQL.

### Вариант А: Render через Blueprint (быстрее всего)

В корне лежит [render.yaml](render.yaml) — Render прочитает его сам:

1. Запушьте репозиторий на GitHub.
2. https://render.com → **New → Blueprint** → выберите репозиторий.
3. Render покажет переменные с пометкой *sync: false* — впишите `BOT_TOKEN`,
   `ADMIN_TG_IDS`, `P24_DB`. `BASE_URL` оставьте пустым.
4. **Apply** → дождитесь *Live* → скопируйте адрес вида `https://podrabotka24.onrender.com`.
5. Впишите его в `BASE_URL` (Environment → Save) — сервис перезапустится сам.
6. В **@BotFather**: `/mybots` → бот → *Bot Settings → Menu Button* → тот же HTTPS-адрес.

> **Бесплатный тариф засыпает** после ~15 минут без **входящих** запросов. Опрос
> Telegram — исходящие запросы, сон они не предотвращают: сервис уснёт, и бот
> перестанет принимать объявления. Сообщения при этом не теряются (Telegram хранит
> их до 24 часов и отдаст после пробуждения), но публикация задержится на часы.

Держать сервис живым можно двумя способами, они не мешают друг другу:

- **[.github/workflows/keepalive.yml](.github/workflows/keepalive.yml)** — уже в
  репозитории, дёргает `/api/health` каждые 10 минут и проверяет, что база
  отвечает. Адрес переопределяется переменной репозитория `HEALTH_URL`
  (*Settings → Secrets and variables → Actions → Variables*). У бесплатных
  раннеров расписание плавает на 5–15 минут, а после 60 дней без коммитов
  workflow отключается — это подстраховка, а не основной механизм.
- **Внешний пингер** (UptimeRobot, cron-job.org) на тот же адрес раз в 5 минут —
  надёжнее, рекомендуется как основной.

Проверить, что в проде, можно одним запросом — `/api/health` отдаёт короткий хеш
развёрнутого коммита, канал-витрину и режим бота:

```bash
curl -s https://podrabotka24.onrender.com/api/health
```

> **SQLite на Render эфемерный.** Без `P24_DB` все объявления и пользователи пропадут
> при первом же редеплое. Заведите бесплатную базу на [Neon](https://neon.tech) и
> вставьте её строку подключения в `P24_DB` — таблицы создадутся сами.

#### Где взять строку подключения Neon

1. https://console.neon.tech → ваш проект → панель **Connect** / **Connection string**.
2. Выберите ветку `main`, базу и роль.
3. **Снимите галочку «Pooled connection»** — нужна прямая строка, без `-pooler`
   в адресе. Приложение держит собственный пул (`psycopg_pool`, 1–4 соединения,
   [server/db.py](server/db.py)), а пулер Neon поверх него ломает подготовленные
   запросы psycopg.
4. Нажмите «Show password» — иначе пароль скопируется как `****` и строка не сработает.
5. Строка должна выглядеть так (одной строкой, без переносов):

```
postgresql://neondb_owner:ПАРОЛЬ@ep-xxxx-12345678.eu-central-1.aws.neon.tech/neondb?sslmode=require
```

Часть `?sslmode=require` обязательна. Существующие таблицы не пострадают —
схема создаётся через `CREATE TABLE IF NOT EXISTS`.

> Бесплатный Neon засыпает после ~5 минут простоя, первый запрос после пробуждения
> занимает пару секунд. Таймаут подключения в проекте — 15 секунд, этого хватает.

8. Откройте бота в Telegram → кнопка «Меню». На старте сервер один раз отправит в группу-витрину (`GROUP_ID`) приветствие-пин и приглашение «Подать заявку», а админам — то же приглашение в ЛС бота.

### Вариант В: свой сервер (VPS)

```bash

```

Обязательно проксируйте через **Nginx + HTTPS** (certbot). Без HTTPS Telegram не откроет Mini App.

> **Важно про БД:** Без переменной `P24_DB` используется SQLite (файл `server/p24.db`). Для продакшена задайте `P24_DB` — URL PostgreSQL (например, бесплатный [Neon](https://neon.tech) или Supabase): таблицы создадутся автоматически при старте, данные переживут редеплои. Замена `db.py` не требуется — драйвер выбирается автоматически (`postgres://` или `postgresql://` в `P24_DB`).

## 2.1. Канал-витрина и размещение объявлений

Объявления публикуются в канал из переменной `GROUP_ID` (по умолчанию `@podrabotka_orders`).

**Обязательно:** добавьте бота в канал **администратором** с правом «Публикация сообщений».
Без этого Telegram отклонит отправку, а админам придёт уведомление об ошибке.

Разместить объявление можно двумя путями — оба создают запись в ленте приложения
и карточку в канале:

| Путь | Как | Формат | Карточка в канале |
|---|---|---|---|
| Бот в ЛС | прислать боту одно сообщение | **свободный текст** — как пишут в чат | текст автора, без кнопки |
| Мини-апп | кнопка «Открыть приложение» → форма | поля (тип, адрес, цена, дата) | карточка + кнопка «Открыть заказ» |

Кнопка «Открыть заказ» ведёт в мини-апп и появляется только у объявлений из формы:
там отклик идёт через приложение. Объявление из бота самодостаточно — контакты
автор пишет прямо в тексте, и кнопка была бы лишней.

### Как работает свободная форма

1. Человек пишет боту объявление своими словами — построчно (`Адрес: ...`, `Ставка: ...`)
   или сплошной прозой, как ему удобно.
2. Бот проверяет текст модерацией (см. ниже). Не прошло — объявление не публикуется,
   автор получает причину.
3. Прошло — **сразу публикуется в канал, текст автора без единого изменения**.
   Подтверждения и предпросмотра нет.
4. Параллельно текст разбирается для ленты приложения: тип работы, число людей, цена,
   город, адрес, дата/время, телефон, `@username`. Разбор best-effort и на вид
   объявления в канале не влияет — что не распозналось, остаётся пустым.
5. Автору приходит кнопка «Закрыть вакансию» — карточка в канале помечается закрытой.
   Удаление заказа в приложении помечает карточку как «🗑 Заказ удалён».

Команды бота: `/start` — приветствие, `/help` — как писать объявление.

> Публикация мгновенная, отмены нет. Ошибочное объявление автор закрывает кнопкой
> «Закрыть вакансию» или удаляет в приложении; администратор — удаляет любое.
> Сам пост в канале при этом не исчезает, а помечается закрытым/удалённым:
> у бота нет права удалять сообщения в канале, только редактировать.

### Модерация

Проверка идёт до публикации, на обоих путях ([server/moderation.py](server/moderation.py)):

- **Мат** — по корням слов, с учётом обфускации: латинские двойники (`xyй`), цифры
  вместо букв (`х0й`), разрядка (`х у й`, `х.у.й`), звёздочки (`п**дец`), растянутые
  повторы (`хуууй`). Корни ищутся с начала слова, поэтому «страхуй», «требования»,
  «лебедь», «себестоимость», «веб-разработчик» не дают ложных срабатываний.
- **Запрещённые темы** — наркотики (включая «закладки»/«кладмен»), интим-услуги,
  обнал и отмывание, оружие, поддельные документы, казино, финансовые пирамиды.
  Формулировки узкие: «курьер», «дропшиппинг», «оплата нал» — легальные вакансии
  и не блокируются.
- Свои стоп-слова добавляются через `BANNED_WORDS` (через запятую).

Отклонённое объявление не публикуется, автор получает причину с указанием слова.

## 3. Как это устроено

- **Фронтенд** (ванильный JS): при старте вызывает `POST /api/auth` с `initData`, получает токен сессии и профиль; дальше все данные — через REST API с заголовком `Authorization: Bearer <token>`.
- **Бэкенд** (FastAPI + SQLite): проверка подписи initData, пользователи, заказы, отклики, отзывы, уведомления. БД создаётся и наполняется демо-данными автоматически при первом запуске (`server/p24.db`).
- Если API недоступен (нет сети/сервера) — приложение автоматически работает в офлайн-демо на localStorage.

## 4. Основные эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth` | вход по initData → `{token, user}` |
| GET | `/api/me` | профиль + мои заказы/отклики/уведомления |
| PATCH | `/api/me` | обновить роль/навыки/телефон/имя |
| GET | `/api/orders` | список заказов |
| POST | `/api/orders` | создать заказ |
| GET | `/api/orders/{id}` | карточка заказа |
| POST | `/api/orders/{id}/respond` | откликнуться |
| POST | `/api/orders/{id}/cancel_respond` | отменить отклик |
| POST | `/api/orders/{id}/assign` | назначить исполнителя (автор) |
| POST | `/api/orders/{id}/reject` | отклонить отклик (автор) |
| POST | `/api/orders/{id}/complete` | завершить заказ |
| POST | `/api/orders/{id}/review` | оставить отзыв (1–5 звёзд) |
| POST | `/api/orders/{id}/report` | пожаловаться на заказ (причина + комментарий) |
| DELETE | `/api/orders/{id}` | удалить заказ (автор — свой открытый; админ — любой) |
| GET | `/api/admin/reports` | список жалоб (только админ) |
| POST | `/api/admin/reports/{id}/resolve` | пометить жалобу решённой (админ) |
| GET | `/api/admin/users/blocked` | список заблокированных пользователей (админ) |
| POST | `/api/admin/users/{id}/unblock` | восстановить доступ (админ) |
| POST | `/api/notifications/read` | отметить уведомления прочитанными |

### Модерация

- **Жалоба на заказ** — любой пользователь (кроме автора), одна на заказ. Причина + комментарий.
- **Автоблокировка** — после `BLOCK_THRESHOLD` (по умолчанию 3) новых жалоб на заказы пользователя его аккаунт блокируется: он не может создавать заказы и откликаться (в приложении — баннер с предупреждением).
- **Уведомления админу** — при каждой жалобе и блокировке администраторам из `ADMIN_TG_IDS` приходит сообщение в Telegram (кнопка «Заблокированные» в профиле → «Восстановить»).
